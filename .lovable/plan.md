## 현재 상태 (확인됨)

지금 연결된 Supabase 백엔드를 직접 조회한 결과:
- public 스키마 테이블: **0개**
- 가입 사용자(auth): **0명**

즉 462명의 계정, 문제 풀이 기록(attempts), 교재 등록, 메모, 스터디 그룹 데이터는 **현재 DB에 존재하지 않습니다.**

## 데이터 복구 가능성 (먼저 확인해야 할 것)

프로젝트를 삭제하면 Supabase는 일정 기간 내 **복원(Restore)** 을 제공할 수 있습니다. 코드로는 되살릴 수 없고, 다음 순서로만 가능합니다.

1. Supabase 대시보드 → Organization → **General / Projects** 에서 삭제된 프로젝트가 "Restore" 상태로 남아 있는지 확인
2. 없다면 Supabase 지원팀(support@supabase.io)에 프로젝트 ref와 삭제 시점을 알려 백업 복원 요청 (Pro 플랜은 PITR/일일 백업 보유 가능성 있음)
3. 로컬/다운로드해 둔 SQL 덤프나 CSV 내보내기 파일이 있는지 확인

위 셋 중 하나라도 되면 **데이터까지 완전 복구**, 아니면 **구조만 복구 + 사용자 재가입**입니다.

## 구조 복구 계획 (데이터와 무관하게 즉시 가능)

1. 로컬에 남아 있는 마이그레이션 약 80개를 순서대로 검증 — 삭제/이름변경으로 깨지는 구간 정리
2. 하나의 통합 마이그레이션으로 재구성: 테이블, 컬럼, 인덱스, enum(app_role 등), 함수/트리거, GRANT, RLS 정책 전체
3. 교재 시드 데이터(books) 재삽입 — 강사·과목·교재 목록은 코드/시드에 남아 있어 복원 가능
4. 스토리지 버킷 및 정책 재생성
5. Google OAuth 등 인증 provider 재설정 (대시보드 작업, 안내 제공)
6. 앱에서 회원가입 → 온보딩 → 교재 등록 → 채점 입력까지 실제로 한 바퀴 돌려 동작 검증

## 기술 참고

- 재연결 대상 프로젝트가 명확해야 합니다. 현재 도구가 붙은 프로젝트와 앱 `.env`의 프로젝트가 다르면 복구가 엉뚱한 곳에 적용됩니다.
- 사용자 데이터가 복원되지 않는 경우, 기존 이용자에게는 재가입 안내가 필요하며 랭킹·연속기록은 0부터 시작됩니다.
